# Dev, prod и медиа Bon

Хостинг REG.RU Host-Lite, без серверной CMS и базы данных.

| | Dev | Prod |
|---|---|---|
| Ветка | develop | main |
| Сайт | https://dev.bonatlas.ru | https://bonatlas.ru |
| Админка | /cms/ | /cms/ |
| Каталог | /www/dev.bonatlas.ru | /www/bonatlas.ru |
| Медиа | свой /uploads/ | свой /uploads/ |
| Публикация | после push | ручной запуск deploy-prod |

## Работа

1. Изменения кода, статей и настроек сохраняются в develop.
2. GitHub Actions проверяет код, собирает сайт и публикует dev.
3. В dev показываются черновики; поисковая индексация запрещена robots.txt и noindex. Это не парольная защита: dev доступен по ссылке.
4. После проверки переносим одобренные изменения в main. Merge переносит также тексты и ссылки на медиа.
5. Push в main только проверяет и сохраняет сборку на хостинге, основной сайт не меняется.
6. GitHub → Actions → Build and publish BON → Run workflow → main → deploy-prod активирует эту сборку без повторного построения.

## Медиа отдельно от Git

Исходники картинок и видео остаются локально в public/images и public/uploads.
В Git хранится media-manifest.json с адресами, размерами и SHA-256.
Ранее добавленные изображения остаются в истории Git; история не переписывается.

Команды выполняются из корня репозитория (пароль запрашивается скрыто):

```text
python scripts/media.py register
python scripts/media.py upload --environment dev
python scripts/media.py upload --environment prod
```

При обращении «загрузи медиа на dev» агент выполняет отдельную FTPS-загрузку.
Перед выпуском на prod аналогично загружаются нужные файлы на prod.
Каждая версия имеет собственный адрес /uploads/<sha256>/<имя>.
Старые файлы не перезаписываются и не удаляются при публикации кода.
В CMS указываем URL медиа в соответствующем поле. Штатная загрузка в Git отключена в выдаваемой конфигурации CMS.
Файлы публичного сайта доступны по прямой ссылке.

## Версии и восстановление

Сборки: /bonatlas-releases/<dev|prod>/staged/<commit>, вне публичной папки.
Резервные копии кода: /bonatlas-releases/<dev|prod>/backups/<дата>.
До публикации проверяются все медиа и целостность сборки, затем сохраняются прежние файлы кода.
Публикация заменяет файлы по одному через временные файлы; единого атомарного переключения всего сайта на этом тарифе не настроено.
При ошибке публикации или HTTPS-проверки возвращается предыдущий код.
Старые страницы, удалённые из сборки, удаляются с сайта, чтобы снятый материал не оставался доступен по URL.
Медиа сохраняются отдельно, резервная копия кода их не меняет.

В Actions: rollback-prod + backup=previous возвращает последнюю резервную копию.
list-prod показывает доступные сборки и резервные копии; можно выбрать конкретный ID.
Резервные копии пока не очищаются автоматически; за общим лимитом 7 ГБ нужно следить.

Секрет REG_FTP_PASSWORD хранится только в GitHub Actions Secrets или памяти локального процесса.
Никаких платных внешних хранилищ схема не использует.
