# Публичные сведения Bon Plot: отправка из закрытого проекта

Сайт не получает ключа от закрытого репозитория программы. Утверждённый паспорт отправляет
сам `blizzjk-gif/bon-plot`. Доступные файлы: `/product-info/bon-plot.json` и `bon-plot.md`.
Начальный пакет уже находится в public/product-info. Новый домен, сервер и MCP не нужны.

## Разовая настройка владельцем

1. Создать fine-grained GitHub token: Only select repositories → **bonatlas-site**.
   Repository permissions: **Contents: Read and write**, **Pull requests: Read and write**.
   Остальные права не добавлять. Доступ к bon-plot не выдавать. Задать срок действия.
2. В ЗАКРЫТОМ репозитории программы открыть
   https://github.com/blizzjk-gif/bon-plot/settings/secrets/actions → New repository secret.
   Имя: **BON_SITE_PUBLISH_TOKEN**, значение — созданный токен.
   В чат и исходники значение не передавать. На стороне сайта этот ключ не хранится.
3. В Actions проекта bon-plot выбрать **Send public Bon Plot facts to website** → Run workflow → main.
4. Проверить результат: unchanged — справочник уже актуален; proposed — появился PR сайта.
   Прочитать PR и принять при согласии. not-configured означает, что отправка ещё не подключена.

Старый BON_PLOT_READ_TOKEN и разрешение GITHUB_TOKEN сайта создавать PR для этой схемы
не нужны. Если старый секрет/токен созданы, удалить секрет сайта и отозвать старый токен.
Создание PR выполняется отдельным токеном владельца, а не GITHUB_TOKEN сайта.

## Как обновляется сайт

В закрытом проекте подготовка проверяет утверждение, контракт и отсутствие непубличных
данных. Затем отдельный job получает только публичный пакет и служебный отправитель.
В этом job нет checkout исходников программы, нет запуска кода сайта и нет права Contents
у штатного GITHUB_TOKEN. Отдельный BON_SITE_PUBLISH_TOKEN имеет права только на bonatlas-site.

Отправитель читает текущие публичные файлы через GitHub API и при изменении создаёт коммит
в отдельной ветке и PR. Только три пути: public/product-info/bon-plot.json, bon-plot.md и
editorial/product-updates/bon-plot.md. Остальные файлы дерева сохраняются; main и существующие
ветки не перезаписываются. Автослияния нет. Повтор и уже рассмотренные редакции не создают новый PR.

Отправка запускается при изменении утверждённого публичного пакета в main программы,
также доступен ручной запуск. Ежедневного опроса из проекта сайта нет.
Workflow сайта **Validate received Bon Plot public facts** выполняет только read-only проверки
входящего справочника и его контракта. Существующий deploy-workflow не менялся.

## Границы доступа

Передаются только released-функции и ограничения для пользователя. Эксперименты, планы,
внутренние evidence, рабочий номер версии, баги, пароли, настройки и книги не передаются.
Закрытый catalog.json остаётся в bon-plot. Отправитель проверяет, что Markdown точно
соответствует публичному JSON, даже если кто-то пересчитал контрольные суммы вручную.

Хеш подтверждает конкретное содержимое, а не является электронной подписью издателя.
GitHub-токен имеет write-права на репозиторий сайта целиком, а не только три файла:
ограничение путей и отсутствие автослияния обеспечивает код отправителя. При утечке токена
возможна нежелательная запись в сайт; доступа к закрытому bon-plot этот токен не даёт.

Страница /plot/, CONTENT_SPEC и статьи автоматически не переписываются. Контентный агент
читает справочник и редакционное задание, сохраняет ограничения и готовит правки владельцу.
Платные LLM-запросы не выполняются. Разрешение на публикацию статей этим заданием не даётся.

## Локальная проверка сайта без доступа к программе

```powershell
node --test tests/product-sync.test.mjs
node scripts/sync-bon-plot.mjs --verify-public
```

Проверка отправителя и безопасный --dry-run находятся в проекте программы. Не передавать
публичному сайту credential для чтения закрытого репозитория ради этих проверок.
