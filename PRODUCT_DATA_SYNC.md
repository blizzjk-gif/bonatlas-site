# Получение публичных сведений Bon Plot

Источник: blizzjk-gif/bon-plot, ветка main, только docs/product/generated.
Новый домен, сервер и MCP не нужны. На существующем сайте размещаются два справочных файла:
`/product-info/bon-plot.json` и `/product-info/bon-plot.md`.

## Что допускается передавать

Только утверждённый публичный пакет: функции released и ограничения их использования.
Рабочая версия кода, экспериментальные функции, планы, evidence, баги, пароль разработчика,
настройки и книги не передаются. Закрытый catalog.json остаётся в репозитории программы.
Приёмник отклоняет preview/planned даже в правильно подписанном хешем пакете.
Хеш проверяет содержимое и согласование, а не является электронной подписью издателя.

## Первоначальная настройка владельцем

1. Изменения подключения и утверждённый пакет должны быть отправлены в main обоих репозиториев.
2. В GitHub создать fine-grained token: доступ только к blizzjk-gif/bon-plot,
   разрешение **Contents: Read-only**. Задать срок действия.
3. Открыть https://github.com/blizzjk-gif/bonatlas-site/settings/secrets/actions
   → New repository secret. Имя: **BON_PLOT_READ_TOKEN**. Значение вводит владелец
   самостоятельно; не присылать в чат и не сохранять в исходники или браузерный код.
4. Settings → Actions → General → Workflow permissions: разрешить GitHub Actions
   создавать pull requests, если настройка отключена. Токен чтения программы не имеет прав записи;
   для PR сайта workflow использует свой GITHUB_TOKEN с ограниченными правами.
5. Actions → Review Bon Plot product facts → Run workflow → main.
6. Проверить результат: нет изменений — пакет уже актуален; при изменениях появляется PR.
   Прочитать его и принять при согласии. Автоматического слияния и публикации статей нет.

В первый push включён проверенный начальный публичный пакет, поэтому после обычной публикации
сайта справочник уже доступен; секрет требуется для дальнейшего автоматического обновления.
Существующий порядок активации production сохраняется.

## Дальнейшая работа

Workflow ежедневно около 08:37 по Екатеринбургу (03:37 UTC, возможна задержка GitHub)
или вручную читает пакет. Черновик не заменяет текущие публичные файлы. Повреждённый пакет,
откат редакции и изменение фактов без revision дают ошибку без публикации.
Повтор без изменений не перезаписывает файлы и не создаёт новый PR. Закрытое предложение
той же редакции не открывается повторно. Если доступ не настроен, workflow явно пишет об этом.
При истечении токена владелец обновляет секрет; прежний справочник остаётся на месте.

Передаваемые файлы: public/product-info/bon-plot.json, bon-plot.md и внутреннее задание
editorial/product-updates/bon-plot.md. Отчёт тоже содержит только изменения публичных фактов.
Страница /plot/, CONTENT_SPEC и статьи этим инструментом не переписываются.

Контентный агент читает публичный JSON и редакционное задание, сверяет тексты с выпущенной
программой, сохраняет ограничения, следует CONTENT_SPEC и правилам editorial/STYLE_GUIDE.md.
Расхождения передаёт владельцу на проверку. Самостоятельный запуск LLM не подключён.

## Локальная проверка

```powershell
node --test tests/product-sync.test.mjs
node scripts/sync-bon-plot.mjs --source "PATH_TO_BON_PLOT_REPOSITORY" --check
node scripts/sync-bon-plot.mjs --source "PATH_TO_BON_PLOT_REPOSITORY" --review
```

--check ничего не записывает. --review создаёт только внутреннее редакционное задание.
Без флага утверждённый пакет записывается в public/product-info, а черновик пропускается.
