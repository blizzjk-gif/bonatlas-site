# Серверные изменения для SEO

Эти изменения подготовлены по HTTP-проверке 02.11.2026. Они не применены: репозиторий управляет статическими файлами через FTP, конфигурация nginx и доступ к её перезагрузке в этом процессе отсутствуют. Не загружать этот документ в web-root и не подменять действующий server-блок целиком.

## Формат адресов

Сайт теперь собирается с конечным слешем: `/atlas/`, `/plot/`, `/blog/` и статьи `/blog/<slug>/`. Это соответствует уже работающим редиректам nginx. Sitemap, canonical и внутренние ссылки используют тот же формат. Отдельный `/atlas/app/` принадлежит редактору; его location, proxy, файлы и правила обратной связи сохраняются.

## Основное зеркало

В панели хостинга установить основным зеркалом `https://bonatlas.ru` и постоянный редирект с www с сохранением пути и query string.

Если изменения делает администратор nginx: в существующий HTTPS server-блок, обслуживающий оба имени, после настройки действующего сертификата добавить условие только с return:

```nginx
if ($host = www.bonatlas.ru) {
    return 301 https://bonatlas.ru$request_uri;
}
```

В существующем HTTP-блоке для этих доменов конечная цель редиректа:

```nginx
return 301 https://bonatlas.ru$request_uri;
```

Сохранить действующее обслуживание ACME/.well-known при продлении сертификата. Сертификат для www должен оставаться действительным: TLS устанавливается до редиректа. Не переносить это правило на dev.bonatlas.ru.

## Кеширование новых медиа

В существующем правиле кеширования изображений добавить расширения webp, avif и svg. Для URL `/uploads/<sha256>/...` допустим длительный max-age с immutable: содержимое по адресу не меняется. Правило не должно перехватывать HTML, JSON редактора, `/atlas/app/` и API. Старые PNG и адреса медиа не удалять.

## Оформленная 404

В основном существующем server-блоке можно настроить:

```nginx
error_page 404 /404.html;
```

Сохранить код ответа 404. Перед применением проверить, не меняет ли общее правило обработку ошибок редактора и API; при необходимости ограничить правилом статического сайта.

## Проверка после применения

1. `nginx -t`, затем штатная перезагрузка nginx администратором.
2. `http://bonatlas.ru/atlas/` и `https://www.bonatlas.ru/atlas/` ведут прямо на `https://bonatlas.ru/atlas/`, без `:443` и лишней цепочки.
3. Пути и параметры редактора сохраняются при переходе с www; на основном домене `/atlas/app/` работает как прежде.
4. Все страницы sitemap отвечают 200 без редиректа, canonical совпадает с URL.
5. Несуществующая страница отвечает 404; WebP получает согласованный Cache-Control.
